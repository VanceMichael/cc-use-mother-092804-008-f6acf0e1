# 铁路便民服务预约与现场交接

协调铁路重点旅客、宠物托运、行李搬运和临时证明确认的后端。

## 参与方与事实

主要参与方包括旅客、车站工作人员、客运服务主管、宠物托运人员、行李承运人员和列车长。领域资料记录以下已经确认的事实：

- 铁路平台提供重点旅客预约、爱宠行、轻装行和临时身份证明服务
- 重点旅客服务覆盖老人、孕妇和需要辅助设备的旅客
- 宠物托运覆盖指定车站和车次并受体型条件约束
- 线上预约按稳定受理锚点去重，关键字段变化进入人工确认而非重复受理
- 重点旅客资格核验通过后沿车次停站生成分段接力任务
- 宠物可单独出行但必须指定到站接收人，行李可跨站运输且件数全程守恒
- 旅客取消或列车调整只影响尚未发生的环节，已完成的接送与交接永久留痕

## 业务约束

- 资格核验：重点旅客先核验类别与依据，核验通过后才生成分段接力
- 服务时间窗：派工与交接必须落在环节窗口内，临时证明窗口随有效期限截止
- 件数守恒：每次交接核对登记件数，件数不符中止交接；前序已交接则后序不可撤销
- 局部取消：只撤销尚未发生的环节，已完成的接送与交接仍可追溯
- 现场交接：站点、岗位、时间窗、交接双方与件数逐项落实
- 重复请求返回同一预约；关键字段变化进入人工确认，批准后重排、驳回后维持原状
- 宠物校验物种白名单与笼箱尺寸重量；行李校验件数上限与沿车次路线
- 最小知情：值班人员只看到本岗位本环节的最小信息；管理者可还原完整责任链

## 代码结构

```
src/railway/
  models.py       旅客、同行关系、车次、资格、托运物件、站点、时间窗、环节与交接
  policies.py     物种尺寸规则、件数与路线守卫、站点车次网络
  reservation.py  预约聚合与分段接力规划（语义稳定的环节 ID、改签重排、局部取消）
  backend.py      受理去重、人工确认、资格核验、列车调整、派工交接、过期清理
  views.py        值班员最小视图与管理者责任链还原
tests/            52 个脱敏用例，覆盖全部业务约束
```

`contracts/context.schema.json` 描述资料结构，`fixtures/context.json` 提供不含真实身份信息的示例，`src/railway_service_context.py` 负责读取和校验这些资料。

## 开发命令

运行测试：

```bash
python3 -m unittest discover -s tests -v
```

编译检查：

```bash
python3 -m compileall -q src
```

两条命令只读取仓库内文件，不需要连接外部业务系统。
