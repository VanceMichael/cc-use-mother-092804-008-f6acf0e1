# 铁路便民服务预约与现场交接

协调铁路重点旅客、爱宠行（宠物托运）、轻装行（行李服务）和临时身份证明的线上预约与车站现场交接。

## 参与方与事实

主要参与方包括旅客、车站工作人员、客运服务主管、宠物托运人员、行李承运人员。领域资料记录以下已经确认的事实：

- 铁路平台提供重点旅客预约、爱宠行、轻装行和临时身份证明服务
- 重点旅客服务覆盖老人、孕妇和需要辅助设备的旅客
- 宠物托运覆盖指定车站和车次并受体型条件约束

## 业务约束

- 资格核验：重点旅客先核验类别资格，核验通过后才生成分段接力任务
- 服务时间窗：每个环节必须落在旅客预约窗口内
- 件数守恒：行李交接按件标识核对，漏件、串件、多件一律拒绝
- 局部取消：旅客取消或列车调整只撤销尚未发生的环节，已完成的接送交接保留可追溯
- 现场交接：相邻环节在车站当面交接并留痕，形成责任链

`contracts/context.schema.json` 描述资料结构，`fixtures/context.json` 提供不含真实身份信息的示例，`src/railway_service_context.py` 负责读取和校验这些资料。

## 后端结构

后端只依赖 Python 标准库（≥3.11），分层清晰：

| 模块 | 职责 |
| --- | --- |
| `src/models.py` | 预约、旅客与同行关系、行程、四类服务需求、接力任务、交接记录、复核单、领域事件 |
| `src/catalog.py` | 车站、车次时刻、值班人员、宠物/行李/重点旅客政策（虚构种子数据） |
| `src/planning.py` | 纯函数规划器：重点旅客分段接力、宠物/行李/临时证任务生成与规则校验 |
| `src/builder.py` | 请求结构校验与领域对象构造；按关键字段计算幂等指纹与变更差异 |
| `src/repository.py` | 带锁的内存存储，保证并发下同一幂等键只受理一次 |
| `src/service.py` | 应用服务：提交、人工复核、资格核验、交接、局部取消、列车调整、证明查验 |
| `src/views.py` | 值班人员最小信息视图、车站值班台、管理人员责任链还原 |
| `src/api.py` | `http.server` JSON 适配层，只做协议转换 |

### 关键行为

- **四服务一单**：重点旅客陪护、宠物托运、行李搬运、临时身份证明可在同一预约中提出，共享预约号与车次
- **重复不重办**：相同 `idempotency_key` 的重复请求返回同一预约；关键字段（旅客/同行关系、车次乘降站、服务内容）变化时进入人工确认，等待期间冻结变更；时间窗等非关键字段变化直接幂等返回
- **宠物单独出行**：宠物可挂单独车次，校验物种、笼具尺寸、重量、指定车站与车次
- **行李跨站运输**：行李可走与旅客不同的路线与车次，守住每单件数、单件重量与路线方向
- **临时证明期限**：证明在核验出具时生成编号与到期时刻，超期不可交付，查验接口返回有效期状态
- **只撤销未发生环节**：完成的环节不可变；改签时完成的（环节, 站点）不重建，开放环节改期或撤销；规则校验失败时原方案不受污染

### HTTP 接口

| 方法与路径 | 说明 |
| --- | --- |
| `POST /bookings` | 提交预约（带 `idempotency_key`），重复返回同一单，关键字段变化返回复核单 |
| `GET /bookings/{id}` | 预约摘要（任务、指派、状态） |
| `GET /bookings/{id}/chain?service=` | 管理视图：从预约到完成的责任链与事件时间线 |
| `POST /bookings/{id}/eligibility` | 重点旅客资格核验（approved/note） |
| `POST /bookings/{id}/tasks/{task}/start` | 被指派人开始环节 |
| `POST /bookings/{id}/handovers` | 完成当前段并现场交接（objects 为对象清单，行李按件核对） |
| `POST /bookings/{id}/tasks/{task}/complete` | 完成末段（送达/交付/证明递交，超期证明被拒） |
| `POST /bookings/{id}/cancel` | 整单或单项局部取消 |
| `POST /bookings/{id}/adjust` | 列车调整（main/pet/luggage 分别给新行程） |
| `GET /reviews`、`POST /reviews/{id}/resolve` | 人工确认队列与受理/驳回 |
| `GET /staff/{staffId}/tasks` | 值班人员本人任务的最小信息视图（`all=1` 含已完成） |
| `GET /stations/{code}/dashboard` | 车站值班台开放环节 |
| `GET /certificates/{no}?at=` | 临时身份证明有效期查验 |

操作人通过 `X-Staff-Id` 请求头传递；错误统一返回 `{"error":{"code","message"}}`，业务规则错误为 422。

启动服务：

```bash
python3 -m src.api --host 127.0.0.1 --port 8080
```

## 开发命令

运行测试：

```bash
python3 -m unittest discover -s tests -v
```

编译检查：

```bash
python3 -m compileall -q src tests
```

两条命令只读取仓库内文件，不需要连接外部业务系统。测试数据（车站、车次、人员、姓名）均为虚构。
